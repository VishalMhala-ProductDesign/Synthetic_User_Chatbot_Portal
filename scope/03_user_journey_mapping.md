
## User Journey Mapping
**Input to User Journey Mapping** | Jobs + goals from JTBD Analysis

## Objective
The primary objective of Journey Mapping is to **understand the user's complete experience across a process, identify friction and unmet needs, and discover opportunities for improvement or innovation.**

## Helps to Identify
| Objective | What you learn |
|---|---|
| **1. Understand the current experience** | What the user does from beginning to end |
| **2. Identify user goals** | What the user is trying to accomplish at each stage |
| **3. Find pain points** | Where users struggle, get confused, wait, or abandon |
| **4. Understand emotions** | How users feel at different stages |
| **5. Identify decision points** | Where users make important choices |
| **6. Find dependencies** | Which people, systems, data, or processes affect the journey |
| **7. Identify opportunities** | Where UX, automation, AI, or process changes can help |
| **8. Define the desired journey** | What the improved experience should look like |

## Example
| Journey Stage | User Goal | Activities / Actions | THINKS | FEELS | Pain Points / Friction | Key Decision | Opportunity |
|---|---|---|---|---|---|---|---|
| **1. Prepare** | Get everything ready | Gather data, models, requirements; prioritize tasks and plan time | "Do I have all the right data? What should I tackle first?" | Concerned | Missing/inconsistent data; competing priorities | Is the data ready? | Automated data-quality checks + smart task prioritization |
| **2. Validate Data** | Ensure data is reliable | Check quality, timestamps, synchronization | "Can I trust this data?" | Frustrated | Manual validation, synchronization issues | Is data good enough? | AI-assisted validation |
| **3. Configure Model** | Prepare simulation | Configure model and parameters | "Are my assumptions correct?" | Uncertain | Complex configuration | Is the model ready? | AI configuration assistance |
| **4. Run Simulation** | Generate results | Execute simulation, monitor run | "Why is this taking so long?" | Frustrated | Computational intensity / failures | Did the simulation run successfully? | Intelligent monitoring / failure prediction |
| **5. Validate Results** | Trust the output | Review results, investigate unexpected anomalies | "Can I rely on these results?" | Cautious | Model drift, unexpected results | Are results valid? | AI anomaly detection + explanation |
| **6. Analyse Scenarios** | Understand implications | Compare scenarios and outcomes | "Which scenario is better?" | Analytical | Large amount of information | Which option should I recommend? | AI scenario comparison |
| **7. Ensure Regulatory Compliance** | Confirm the recommended scenario is compliant | Work with regulatory experts, check permitting requirements | "Will this pass regulatory review?" | Anxious | Complex, evolving regulations; permitting delays | Is this scenario compliant? | AI compliance checklist / regulatory-change alerts |
| **8. Communicate** | Align stakeholders | Share findings and recommendations | "How do I explain this?" | Responsible | Stakeholder coordination | What should I recommend? | AI-generated insights / summaries |
| **9. Monitor / Follow-up** | Ensure continued performance | Monitor outcomes, address issues, stay current with industry/regulatory changes | "Has anything changed?" | Alert / attentive | Continuous monitoring; keeping skills/knowledge current | Does this need attention? | AI monitoring and alerts + curated industry updates |
